# 决策记录：tool-portal

## 2026-07-05 接入统一项目中枢

决定：新增 `PROJECT.md`、`AGENTS.md`、`CLAUDE.md` 和 `_ai/`，作为 Claude Code 与 Codex 的共同入口。

## 2026-07-19 管理后台与访问控制

决定：用一个本地回环 Node 服务管理状态，由生成式 Nginx `map` 在目标地址层强制执行“上线、隐藏、需要密码”。页面隐藏只是展示结果，不作为安全边界。

原因：现有工具主要由 Nginx 静态托管，沿用原有 Basic Auth 可以避免引入新的公网会话和密码存储，同时能覆盖直接访问 URL 的情况。

决定：`config/catalog.json` 作为全部管理对象、路由和默认状态的唯一清单；运行时状态单独保存在生产机 `/var/lib/toolbox-control/state.json`，部署不能覆盖它。

决定：外部服务器上的项目仅提供网关入口控制，并在后台明确标记；不把入口隐藏或加密表述成对外站本身的访问控制。

## 2026-07-19 项目级独立密码取代可分享的共用总密码

决定：管理员总密码仅用于管理后台和受保护板块/页面。需要分享给伙伴的具体项目必须使用项目独立用户名、独立密码文件和独立认证域；项目 A 的凭据不能通过项目 B。

这条决定取代上一条中“所有受保护项目都沿用现有 Basic Auth 文件”的分享场景。旧共用密码项目为避免突然锁死暂时保留并明确警告；新项目进入密码模式前必须先设置独立密码。

决定：项目密码使用 OpenSSL SHA-512 crypt 加盐哈希，只把用户名和更新时间写入元数据。后台不保存、展示或返回可恢复的明文密码；用户关闭设置弹窗后只能重新设置。

决定：工具箱首页和商业工具页的渲染文件由回环控制服务提供，不再用“trailing-slash URL + 单文件 alias”的 Nginx 组合，避免继承 index 后产生文件名拼接 500。

## 2026-07-19 公开仓库推送安全门

决定：在用户明确当前 V2 和内部页面的公开边界，并决定如何处理已启用的 GitHub Pages 与历史 `.github/workflows/deploy-my.yml` 之前，不将当前未跟踪的 V2 控制服务、运营后台和内部仪表盘整体推送到公开 `main`。

原因：GitHub Pages 会直接公开仓库静态文件，不执行生产 Nginx 生成的隐藏/密码策略；而生产 V2 已由 dirty 工作区部署，远端 `main` 仍是旧版。生产真相与 Git 发布边界必须先合并成一套可审计流程。

## 2026-07-19 受众、展示与运行状态取代旧 mode 模型

决定：访问策略 schema v2 将旧的“上线、隐藏、需要密码”单一 mode 拆成三个独立维度：`audience` 决定 `public`、`owner`、`shared` 受众，`listed` 决定是否展示在公开页，`status` 决定 `online`、`maintenance`、`offline` 运行状态。

这条决定取代前述把展示和认证绑定在同一个 mode 的模型。公开入口只出现在公开工具箱；本人入口只进入受管理员总密码保护的工作台；伙伴入口必须配置项目独立凭据后再分享。维护和下线由 Nginx 在认证之前强制执行。

当前生产 schema v2 默认分组为 28 个 `public` 管理对象（19 个内容项目 + 9 个板块/页面）、8 个 `owner` 项目、4 个 `shared` 项目，40 个对象均在线；4 个分享项目尚未配置独立凭据，设置前仅管理员总密码可访问。

## 2026-07-19 暂不建设开放注册，保留邀请制升级路径

决定：当前不建设统一用户注册后台。公开项目直接开放，`owner` 项目由管理员总密码保护，`shared` 项目使用每项目独立密码，已经覆盖现有三类受众。

原因：开放注册会立即引入账号审核、找回密码、隐私数据、垃圾注册、离职回收和持续运维，但当前只有 4 个定向分享项目，没有足够收益。只有出现大量成员频繁变化、同一成员跨多个项目、操作审计或角色授权需求时，再升级为邀请制账号系统。

## 2026-07-19 认证规则固定使用原始请求 URI

决定：Nginx 权限 map 以 `$request_uri` 派生的原始路径为键，不以可能被 location rewrite 改写的 `$uri` 为键。

原因：`/cohort-api/` 和 `kkhc.fun/admin/` 会在 location 内 rewrite；Basic Auth 在访问阶段读取 map 时，如果使用改写后的 `$uri`，会得到默认公开值。改用原始路径后，两个直达面均在最终内容前返回 401。

## 2026-07-19 动态非空板块与唯一总控台

决定：访问策略 schema v3 在固定页面、内容项目之外新增运行时动态板块。每个内容项目和可分组页面必须且只能属于一个板块；板块可创建、改名、排序、切换公开页面并接收项目移动。

决定：系统不保留空板块。创建板块必须在同一事务中指定首个成员；成员移动后，如果来源板块失去最后一个成员，来源板块立即自动删除。此规则由服务端执行，不能只依赖前端提醒。

决定：板块负责公开目录的分组、顺序和整组展示状态；项目自身的 `audience`、`listed`、`status` 与项目独立密码继续负责真实访问权限。把板块隐藏不等于关闭板块内项目的直达地址。

决定：将原“我的工作台”升级为“磊哥总控台”，作为管理员唯一需要记住的入口；公开页保留醒目但不干扰访客的“磊哥入口”。总控台固定提供公开工具箱、公开商业工具、我的私人工具和管理后台四个入口。

原因：此前板块和项目归属写死在 HTML 中，后台只能调权限，不能调组织结构；管理入口又分散在多个网址。动态板块和总控台把“内容放在哪里”与“谁能访问”分开，降低长期维护成本。

## 2026-07-20 空子页面入口自动隐藏

决定：子页面仅在自身策略可公开、且至少有一个所属板块和内容项目同时满足 `public + listed + online` 时显示入口。条件不满足时，公开首页、磊哥总控台和管理后台的该页面导航同步隐藏。

决定：不删除子页面定义和旧 URL。后续将公开项目放回该页面后，入口自动恢复。

原因：这能避免用户进入“0 个项目”的空页，同时保留历史链接兼容性和未来重新启用子页面的能力。
